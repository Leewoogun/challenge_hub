- **관련**: [ADR-0011](./0011-photo-storage.md)(사진 저장 — **사진이 처음으로 서버 밖으로 나간다**) · [ADR-0006](./0006-stt-strategy.md)(superseded — 외부 AI 의존의 첫 시도였다) · [ADR-0002](./0002-backend-foundation.md)(에러 모델 — fail-open 이 왜 `code` 를 안 쓰는지) · [ADR-0007](./0007-environment-split.md)(환경 분리 — 키 주입)

> 끝나면 읽히지 않는 문서**다. 여기 남겨야 하는 것은 결론이 아니라 **되돌리려는 사람이 부딪혀야

> 근거가 사라지면 **둘 다 "왜 이렇게 번거롭게 했지" 로 보이고 조용히 뒤집힌다.**

## 결정

### 1. **Google Gemini 유료 티어.** 무료 티어는 쓰지 않는다

키는 [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서 발급하고,
**같은 페이지에서 "Upgrade to Paid" 로 Google Cloud 결제 계정을 연결**해야 한다.

🔴 **키를 만들기만 하면 free tier 다.** 계층은 세 겹이다 (2026-09-20 공식 문서 실측):

```
billing account  ← 🔑 티어 · 요율 한도 · 지출 캡이 결정되는 곳
  └ project      ← 자기 billing account 의 상태를 상속
      └ API key  ← 독립 결제 설정이 없다. 프로젝트의 티어·결제 상태를 그대로 상속
```

🔵 **따라서 같은 billing account 에 붙은 프로젝트는 전부 Paid 다** — 프로젝트를 새로 파도
결제 설정을 다시 하지 않는다. ⚠️ **거꾸로, 프로젝트를 나눠도 요율 한도·지출 캡은 격리되지
않는다**(둘 다 billing account 레벨). 프로젝트 분리로 얻는 것은 **비용 가시성과 키 수명**이지
쿼터가 아니다 — 과장해서 근거로 쓰지 마라.

업그레이드 후 API 키 페이지에서 해당 키의 프로젝트가 `Paid` 로 표시되는지 **눈으로 확인**한다 —
이 확인을 건너뛰면 §근거 1 의 방어가 통째로 무효다.

⚠️ 2026-03-23 이후 신규 계정은 **선불(Prepaid)** 플랜으로 배정될 수 있다(크레딧 선충전 필요).
2026-03-02 이후 개설 계정의 GCP 무료 크레딧은 Gemini API 결제에 쓸 수 없다.

**Vertex AI 경로는 쓰지 않는다** — 서비스 계정 JSON + GCP 프로젝트 설정이 붙는데, 우리 호출은
단순 아웃바운드 1건이라 AI Studio 키 하나로 충분하다.

### 2. 🔴 **AI 는 승패를 결정하지 않는다** — 사진 1장의 pass/fail 만 답한다

**이 절이 이 ADR 의 본체다.**

```
AI 가 답하는 것    : "이 사진이 이 미션을 수행한 증거인가"   (사진 1장 → 판정 1개)
AI 가 답하지 않는 것: "누가 이겼는가"                        (← ChallengeVerdict 의 몫)
```

```json
{ "missionVerifiable": true, "verdict": "PASS | REJECT | UNCERTAIN",
  "confidence": 0.0, "reason": "한 줄 사유" }
```

Gemini 구조화 출력(`responseMimeType: "application/json"` + `responseSchema`)으로 강제한다.

**미인증 처리는 세 조건이 전부 참일 때만:**

```
missionVerifiable == true  AND  verdict == "REJECT"  AND  confidence >= 0.8
```

🔑 **`missionVerifiable` 이 핵심이다.** 미션이 자유 텍스트라 *"일찍 자기"*, *"짜증 안 내기"* 처럼
사진으로 검증 불가능한 미션이 섞여 들어온다. AI 에게 *"판정하라"* 가 아니라 **"판정할 수 있는
종류인지 먼저 판단하라"** 를 시키면 오탐의 가장 큰 원인이 앞에서 잘린다.

그 결과를 **기존 `ChallengeVerdict` 가 받아 승패를 낸다.** 🔴 **`ChallengeVerdict` 는
*"판정 규칙이 존재하는 유일한 곳"* 이고 이 feature 는 그 성질을 깨지 않는다** — 근거는 §근거 2.

### 3. 호출 단위 — **제출된 인증 1건당 정확히 1회**

| | |
|---|---|
| 시점 | **자정 판정 배치의 앞단** (실시간 판별 안 함) |
| 대상 | 마감 시점의 **최종본 1장**. 마감 전 교체는 자유이고 호출을 늘리지 않는다 |
| 미제출 건 | **호출 0회** |
| 기권 건 | **호출 0회** — 즉시 `COMPLETED` 라 배치 대상 쿼리에서 자연히 빠진다 |
| 멱등 | `ai_checked_at` 이 있으면 재호출하지 않는다. 배치를 두 번 돌려도 AI 는 한 번만 부른다 |

⚠️ **기권 건을 AI 대상에 되돌려 넣지 마라.** 그 승리는 인증이 아니라 **기권에서 나온 것**이라
사진을 볼 이유가 없다 (근거: [challenge-forfeit/spec.md](../features/challenge-forfeit/spec.md) §3.1).

### 4. **fail-open** — AI 가 죽으면 기존 동작으로 떨어진다

**키 미설정 / 호출 실패 / 타임아웃 / 스키마 파싱 실패** 네 경우 전부 *"사진이 있으면 통과"* 라는
**이 feature 이전의 규칙**으로 되돌아간다. 판정을 막지도, 에러로 세우지도 않는다.

🔵 **`NoOpNotificationSender` 선례를 그대로 잇는다** — `push-fcm` 이 그 격리 덕분에 Firebase
프로젝트를 기다리지 않고 백엔드를 완성했다. 여기서도 **키가 없는 상태로 서버 전체를 완성·테스트할
수 있어야 한다**(`${GEMINI_API_KEY:}` 빈 기본값).

⚠️ **fail-open 은 `code` 를 쓰지 않는다.** 사용자에게 보이는 실패가 아니라 **배치 내부의 성능
저하**이므로 ADR-0002 의 에러 코드 체계와 무관하다. 로그로만 남긴다.

#### 🔴 fail-open 의 대가 — **선불 잔액이 0 이 되면 AI 판별이 조용히 꺼진다**

Gemini 유료 티어는 **선불(Prepay)** 이다(최소 $5, 크레딧 **12개월 만료**, 환불 불가).
잔액이 0 이 되면 **무료 티어로 강등되지 않고 전부 멈춘다** — `429 RESOURCE_EXHAUSTED`
*"Your prepayment credits are depleted"*. ⚠️ **같은 billing account 에 붙은 모든 프로젝트의
모든 키가 동시에** 멈춘다(§결정 1 의 3층 구조 참조).

그 429 는 §결정 4 의 *"호출 실패"* 에 해당하므로 **fail-open 이 발동한다.** 즉:

```
크레딧 0 → 429 → fail-open → "사진이 있으면 통과" 로 복귀
        → 판정은 정상적으로 나가고, 에러도 사용자 불만도 없다
        → 🔴 아무 사진이나 이기는 상태로 조용히 되돌아가 있다
```

🔑 **이건 fail-open 을 폐기할 근거가 아니다.** 반대 설계(AI 실패 시 판정 중단)는 **자정 배치가
통째로 멈추는** 훨씬 나쁜 실패다. 필요한 것은 설계 변경이 아니라 **관측**이다.

🔴 **특히 이 프로젝트의 템포에서 만료가 잔액 소진보다 먼저 온다.** 실사용이 적어 $5 가 남아도는
채로 **12개월이 지나 만료**되는 경로가 더 현실적이다 — 쓰지 않아서 꺼진다.

**방어 2겹** (§결과 §미해결에 등재):
1. **auto-reload 설정** — 잔액 트리거 + 재충전액 + 월 상한. 가장 싼 방어이고 콘솔에서 끝난다
2. **배치가 "AI 판별 스킵 건수" 를 남긴다** — 0 이 아닌 날이 있으면 그날 fail-open 이 돌았다는 뜻.
   🔴 **로그에 묻어 두면 아무도 안 본다** — 스킵 건수는 배치 요약에 **숫자로** 올라와야 한다

### 5. **모델은 설정값이다** — 이 ADR 은 모델을 고정하지 않는다

```yaml
gemini:
  api-key: ${GEMINI_API_KEY:}      # 없으면 fail-open (§4)
  model:   ${GEMINI_MODEL:gemini-3.5-flash}      # 2026-09-20 확정. 🔴 Flash-Lite 아님 — §측정 표
  thinking-level: ${GEMINI_THINKING_LEVEL:low}
```

🔴 **모델 교체에 이 ADR 의 개정이 필요하지 않다.** 고정하는 것은 **제공자(Gemini)와 호출
형태(§2·§3)** 이지 모델 문자열이 아니다 — 근거는 §근거 3.

### 6. `thinking_level` 은 **비용 지배 인자**다 — 모델보다 먼저 정한다

Gemini 3.x 는 추론 모델이고 **내부 사고 토큰이 출력 요율로 과금된다**(가격표 문구가 문자 그대로
*"Output price (including thinking tokens)"*). 응답으로 돌려주지도 않는 사고 과정에 출력 단가를 낸다.

우리 과제는 출력이 JSON 한 줄(~150 토큰)이라 **출력 단가가 거의 안 물리는 구조**인데,
`thinking_level` 하나가 그 전제를 깬다 — §측정 표 참조.

## 근거

### 🔴 근거 1 — 무료 티어를 배제하는 이유는 **한도가 아니라 데이터**다

공식 가격표가 티어별 데이터 정책을 명시한다:

| 티어 | 데이터 |
|---|---|
| Free | Content **used** to improve our products |
| **Paid** | Content **not** used to improve our products |

이 앱이 보내는 것은 **사용자가 미션 수행 중 찍은 개인 사진**이다 — 얼굴·집·직장·생활 반경이
찍힌다. 학습에 넘길 수 없다.

⚠️ **이 근거를 잃으면 판단이 반드시 뒤집힌다.** 용량만 보면 무료 티어로 충분하기 때문이다 —
자정에 20건 남짓이라 2025-12-07 에 50~80% 축소된 무료 할당량으로도 남아돈다. 즉 **"한도가
모자라서 유료를 쓴다" 가 아니다.** 비용을 줄이려는 다음 사람이 *"무료로도 되는데?"* 를
확인하고 내릴 수 있고, 그 순간 조용히 개인 사진이 학습 데이터가 된다.

🔵 부차 사유: 그 2025-12-07 축소 전례 자체가 *"남의 무료 정책에 기능을 묶지 않는다"* 의 근거다.

### 🔴 근거 2 — AI 에게 *"누가 이겼어"* 를 묻지 않는 이유: **규칙의 사본이 생긴다**

사진 2장을 한 번에 넣고 승패를 물으면 **승패 규칙(무승부 · `BOTH_LOSE` · 기권)이 프롬프트 안에
복제된다.** 그러면:

1. **규칙이 두 곳에 산다.** `ChallengeVerdict` 가 바뀌는 날 프롬프트도 따라 바뀌어야 하고,
   안 바뀌면 **아무것도 실패하지 않은 채로 틀린 승패가 나간다**
2. **재현 불가능해진다.** AI 출력은 비결정적이라 같은 사진에 승패가 흔들릴 수 있다.
   지금은 같은 입력이면 같은 판정이 나오는 성질을 `ChallengeVerdict` 가 보장한다
3. **기권·미제출이 AI 를 타게 된다.** §결정 3 의 "호출 0회" 두 줄이 성립하지 않는다

🔵 **`challenge-forfeit` 이 정확히 이 함정을 피한 선례다** — 기권은 규칙 사본을 만들지 않고
`ChallengeVerdict` 안에 **최우선 분기 1개**를 넣고 확정은 **배치의 `judge()` 를 그대로 호출**했다.
*"판정 규칙 3종 변경 0"* 이 그 feature 의 수확이었다. 이 ADR 은 같은 선을 지킨다.

⚠️ **비용은 이 선택의 근거가 아니다.** 장당 1회 × 2회(2.0원)가 2장 1회(1.6원)보다 오히려
0.4원 비싸다 — 프롬프트가 두 번 들어가기 때문이다. **그 0.4원에 규칙의 단일 출처를 산다.**
(미제출·기권 건은 호출 0회라 실사용 평균은 다시 내려간다)

### 근거 3 — 모델을 ADR 에 고정하지 않는 이유

**ⓐ 가격표가 주 단위로 움직인다.** 이 ADR 을 쓰는 2026-09 한 달 안에만 GPT-6 Astra 출시,
GLM-5.3-Flash 프로모 종료(9/9, 전 요율 2배), Gemini 3.5 Flash 입력가 90일간 50% 인하가 일어났다.
**모델 문자열을 ADR 에 박으면 ADR 이 분기마다 낡는다.**

**ⓑ 🔴 리더보드가 우리 과제의 대리 지표일 뿐이다.** 벤치마크는 *"학술 시각 추론"* 을 재지
*"운동복 입고 헬스장에서 찍은 사진이 '주 3회 운동' 미션의 증거인가"* 를 재지 않는다.
그리고 **종합 지능 1위와 비전 1위가 서로 다른 모델이다**(§측정 표). 최종 근거는 리더보드가
아니라 **우리 실제 인증 사진 10~20장 A/B** 다 — 통과해야 할 것과 반려해야 할 것을 섞어서.

**ⓒ 교체 비용이 문자열 1개다.** 같은 계정·같은 키·같은 SDK 안에서 모델 ID 만 바뀐다.
🔵 ADR-0011 §2(`PhotoStorage` 포트)와 같은 형태의 판단이다 — **지금 고정해야 하는 것은
"무엇 뒤에 두느냐" 이지 "지금 무엇을 쓰느냐" 가 아니다.**

### 🔴 근거 4 — **비용은 이 결정의 변수가 아니다.** 그래서 정확도만 보고 고른다

월 600건 기준 최저가(2.5 Flash-Lite) 와 비전 1위(3.5 Flash) 의 차이가 **월 2,600원**이다.
🔴 **반면 오판의 비용은 회복 불가다** — 자정 배치가 판정을 확정하고 `COMPLETED` 로 굳는다.
이의제기 절차를 만들지 않기로 한 이상, **월 2,600원을 아끼려고 판별률을 거는 것은 방향이
반대다.**

⚠️ **다만 "비싼 모델 = 정확한 판별" 도 증명된 명제가 아니다**(근거 3-ⓑ). 그래서 결론은
*"제일 비싼 걸 쓰자"* 가 아니라 **"가격을 근거에서 빼고 A/B 로 정하자"** 다.

### 근거 5 — 문턱(`confidence >= 0.8`)을 **느슨한 쪽**으로 잡는 이유

되돌릴 경로가 없으므로 **비대칭을 그대로 반영한다**:

| 오류 | 결과 |
|---|---|
| 부정행위를 놓침 | 이길 자격 없는 사람이 이긴다. 다음 챌린지가 있다 |
| 🔴 정상 수행자를 반려 | **실제로 미션을 해낸 사람이 진다.** 회복 경로 0 |

**후자가 훨씬 비싸다.** 운영 중 부정행위가 빈발하면 문턱을 올리거나 이의제기를 별도 feature 로
연다 — 그건 관측 후의 일이다.

### 🔴 내려갈 조건을 여기 박는다 — 이게 없으면 "비싼 쪽 출발" 이 영구 정착한다

*"일단 비싼 걸로 시작하고 나중에 내린다"* 는 **나중이 오지 않는 것이 기본값**이다. 내릴 사람이
*"왜 내려도 되는지"* 를 스스로 증명해야 하는데 그 근거가 문서에 없으면 아무도 손대지 않는다.

> `gemini-3.5-flash` 와 전부 일치하면 Flash-Lite 로 내린다.**

> 🔴 **정상 수행자를 반려한 쪽(false reject)이면 내리지 않는다**(§근거 5 의 비대칭).
> 부정행위를 놓친 쪽(false accept)뿐이라면 내려도 된다.

⚠️ **A/B 세트가 없으면 이 판단 자체가 불가능하다.** §결과 §미해결의 *"실사진 A/B 세트 구축"*
이 그래서 🟡 이고, 그것이 끝나기 전에는 **모델을 내리지도 올리지도 마라** — 근거 없이 움직이는
것은 어느 방향이든 같은 실수다.

🔵 **되돌리는 비용은 환경변수 1줄이다**(§결정 5). 이 두 값이 틀린 것으로 드러나도
코드·계약·마이그레이션은 건드리지 않는다.

## 적용 범위

### 지금 적용하는 것

`ai-verification` **하나**다. 자정 판정 배치의 인증 사진 판별.

### 🔴 GLM-5.3-Flash 는 숫자가 이겨도 배제한다

네이티브 멀티모달·MIT 라이선스다. 그럼에도 쓰지 않는다:

- **데이터 처리 정책이 §근거 1 의 기준을 통과하는지 확인되지 않았다.** 우리가 보내는 건
  개인 사진이고, 이건 **가격 이전의 문제**다. 확인 없이 태울 이유가 월 몇백 원에는 없다
- MIT 라 셀프호스팅은 가능하지만 **320B MoE 는 우리 환경(로컬 맥, 미배포)에서 불가능**하다

🔵 **제공자를 늘리는 것 자체가 비용이다** — 키·타임아웃·실패 처리·스키마가 제공자마다 붙는다
(spec §0: *"외부 AI 제공자 호출 0건 — 이 프로젝트 최초"*). 첫 도입에서 둘을 병행하지 않는다.

### 이 ADR 이 **막지 않는 것**

- **모델 교체** — §결정 5. 설정값이고 ADR 개정 불필요
- **다른 용도의 AI 도입** — 이 ADR 은 *"인증 사진 판별"* 에 대한 것이다. 다른 기능이 AI 를
  쓰겠다면 §근거 1(데이터)과 §근거 2(규칙 사본)를 **그 맥락에서 다시 통과해야 한다**

## 결과

**좋은 것**
- 아무 사진이나 올려서 이기는 경로가 닫힌다 — 이 앱의 승리 조건에 처음으로 내용이 생긴다
- **판정 규칙이 여전히 한 곳(`ChallengeVerdict`)에 있다.** AI 를 붙이고도 그 성질이 유지된다
- 키 없이 서버 전체를 완성·테스트할 수 있다(§결정 4) — `push-fcm` 이 Firebase 없이 완성된 것과 같다
- **로컬 서버로 끝까지 검증 가능**해 배포가 선행조건이 아니다

**대가**
- 🔴 **사진이 제3자로 전송된다.** ADR-0011 이 *"서버 로컬 폴더"* 로 닫아 둔 경계가 열린다.
  유료 티어라 학습에는 쓰이지 않지만 **전송 자체가 새로운 사실**이다 → 처리방침 반영 필요
- 🔴 **오탐은 회복 불가다.** 방어는 ⓐ fail-open 4겹 ⓑ 마감 전 무제한 교체 ⓒ `missionVerifiable`
  ⓓ 느슨한 문턱 네 겹뿐이고, *"명백해 보이는데 AI 가 튕긴"* 사례는 남는다. **받아들인 비용이다**
- 외부 의존이 하나 늘었다 — 키 만료·요율 변경·모델 폐기(deprecation)가 우리 판정에 걸린다
- **월 수백~수천 원의 상시 비용**이 처음 생긴다. 지금까지 이 프로젝트의 외부 유료 의존은 0 이었다
