## 2026-09-02

### spec.md — T-M4(Coil 캐시 무효화) 신설 (착수 후 추가)

**원안에 없던 태스크다.** 착수 후에 드러났다.

- **발견 경로**: backend-dev 가 `Cache-Control: max-age=86400` 의 근거가 계약에 *"사진은 재제출
  거부로 불변"* 으로 명시돼 있음을 발견 → 이 feature 가 그 전제를 없앤다는 것. 같은 시각
  mobile-dev 가 `App.kt:79-85` 의 `ImageLoader.Builder` 가 기본값이라 **URL 키 캐시가 켜져 있음**을 실측
- **왜 태스크가 됐나**: 계약은 *"교체 후 캐시 무효화"* 를 모바일 주의사항으로 등재해 뒀는데
  **소유 spec 에는 태스크가 없었다.** 계약·spec·후속 spec 셋이 서로 다른 말을 하고 있었다
  (적발: `verif-mobile-entry`)
- **없었으면**: 사용자가 다시 찍어도 화면이 안 바뀌고, **에러도 로그도 남지 않는다.** 단위 테스트로
  못 잡히며 T-I1 실기에서만 드러났을 항목이다
- 수용 기준에도 *"교체 후 새 사진이 보인다(상대 교체 포함, 실기 육안 확인)"* 를 추가

## 🔴 pm-lead 자기 정정 3건 (2026-09-02)

이 feature 진행 중 pm-lead 가 **실측 없이 단정**해 팀원이 교정한 건들이다. 재발 방지를 위해 남긴다.

**① 해제 기준 자기모순 — 교착 직전**
backend-dev 에게 *"커밋하지 마라"*, mobile-dev 에게 *"계약 개정을 파일로 확인 후 착수"* 라고 지시했는데,
mobile-dev 이 `git log` 로 **커밋**을 찾고 있었다. 커밋이 금지됐으므로 **영영 오지 않을 신호**를
기다리는 상태였다. → 해제 기준을 **working tree 본문**으로 정정하고, "커밋 금지"의 범위가 **코드
레포**임을 명시.

**② 승인을 완료로 기록 — `ai-verification/spec.md` §0**
mobile-dev 의 캐시 키 **제안을 승인한 것**을 "사전 실측" 표에 **✅ 완료**로 적었다. backend-dev 가
`grep memoryCacheKey` → 0건으로 적발. 🔴 **이 실패는 조용해서** ✅ 로 닫혔으면 아무도 구현하지 않고
아무도 실패를 못 봤다. → 표를 서버/앱 두 행으로 분리하고 *"이 표는 실측만 적는다. 판정·승인·계획은
적지 않는다"* 를 규칙으로 명시.

**③ 남의 관측을 내 질문으로 전달**
`verif-mobile-entry` 의 *"`myPhotoDeleted` 필드가 새로 보인다"* 를 확인 없이 옮기며 mobile-dev 에게
**스코프 이탈을 암시하는 형태**로 물었다. 실제로는 회원탈퇴 때 들어온 **기존 필드**였고(`git grep HEAD`
4파일 9건), mobile-dev 은 하지도 않은 일을 해명해야 했다.
