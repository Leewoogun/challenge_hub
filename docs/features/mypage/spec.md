  **월별 조회 + 카드 목록** (캘린더 아님 — 캘린더는 통계 화면 feature 로 이월) ③ 보관함 상세 스펙은
  **design-bridge 협의로 확정**

## 배경

4탭 중 마지막 실속 없는 탭. 기획 IA 정의(내 프로필·통계·계약서 보관함·설정) 중 1차로
**프로필 카드 + 계약서 보관함 + 로그아웃 실구현 + 회원탈퇴 + 설정 골격**을 채운다.
계약서 보관함은 백로그 🟡 **"결과 히스토리 화면 부재"** (홈 7일 노출이 시간벌기)의 정식 해법이자
기획 §3.3(*"이때 너 이거 걸었잖아"* — 증거 보관)의 이행이다.

| 계약서 보관함 화면 | ❌ **Lovable 에 없음** (mypage 메뉴 링크만) — design-bridge 가 신규 명세 |
| 지난 챌린지 상세 | ✅ `GET /challenges/{id}` 가 기한 없이 열림 (계약서·서명·사진·결과) — 목록만 만들면 됨 |
| 로그아웃 | ⚠️ 백로그 🟡 — `LogoutUseCase` 가 서버 `DELETE /auth/logout` 을 안 부른다(엔드포인트는 구현·검증
  완료, 호출부 0). 🔴 선결 사실 2건이 백로그에 있다: `sendWithoutRequest` 술어가 `/auth/logout` 까지
  걸리는 문제(인증 플러그인 전역), `WWW-Authenticate` 실측. clearTokens **앞**에 서버 호출 |
| 회원탈퇴 | ❌ 전부 신규 — 기획서에도 없던 항목(스토어·카카오 요건). 카카오 unlink 방식은 backend 조사 |
| `PhotoStorage.delete()` | ✅ 구현돼 있으나 **호출부 0** (백로그) — 탈퇴의 사진 삭제가 첫 호출부가 된다 |

## 사용자 시나리오

1. MY 탭 → 내 프로필(닉네임·프사)과 전적(총 N챌린지·승률·승/패/무)을 본다.
2. 계약서 보관함 → **월 단위로 묶인 카드 목록**으로 지난 챌린지(상대·미션·내기·결과)를 훑고,
   카드를 탭해 기존 상세(계약서 원문·서명·인증 사진·결과)로 들어간다. *"이때 너 이거 걸었잖아."*
3. 설정 → 로그아웃: 서버 세션(refresh hash·FCM 토큰)까지 끊긴다 — 로그아웃한 기기로 푸시가 오지 않는다.
4. 설정 → 회원탈퇴: 경고 확인 후 탈퇴. 내 개인정보는 지워지되 **상대의 기록(계약서·결과)은 남는다** —
   상대 보관함에서 나는 "탈퇴한 사용자"로 보인다.

## 탈퇴 정책 (사용자 확정 — 익명화 + 기록 보존 + 사진 삭제)

| 대상 | 처리 | 근거 |
|---|---|---|
| `users` 개인정보 (kakao_id·nickname·profile_image_url·phone hash·fcm_token·refresh hash) | **초기화/익명화** — 닉네임 "탈퇴한 사용자" | 개인정보 삭제 의무 |
| 카카오 연결 | **unlink** (방식은 backend 조사 — admin key vs 사용자 토큰) | 카카오 요건 |
| `friendships` | **삭제** — 랭킹은 친구 기반이라 자연 제외 | 관계 종료 |
| 챌린지·계약서·서명·결과·전적(`user_stats`·상대의 `friend_records`) | 🔴 **보존** | 양자 데이터 — 상대의 증거. 컨셉("증거 보존")의 요구 |
| **인증 사진 파일** | 🔴 **삭제** (`PhotoStorage.delete` 첫 호출부) — 상대 화면에는 "탈퇴한 사용자의 사진" 류 표시 | 얼굴이 남는 문제와 증거 보존의 절충 |
| 진행 중(`IN_PROGRESS`) 챌린지 | 오픈 이슈 §리스크 — **자연 판정 권장**(탈퇴자는 인증 불가 → 배치가 상대 승/양패 처리) | 판정 규칙 사본을 안 만든다 |
| 탈퇴자가 보낸 `PENDING` 신청 | **삭제** (2026-08-26 pm-lead 확정 — backend 공백 지적) | 보존할 증거가 0(계약서·서명·사진 전무)이고, 남기면 상대가 수락해 **결과가 정해진 챌린지**를 새로 시작할 수 있다. 기존 "챌린저의 PENDING 취소"(`deleteById`)와 의미 동일. 탈퇴자가 받은 `PENDING` 은 수락 불가라 자연 만료(EXPIRED 배치) |
| 탈퇴자의 `notifications` (수신함) | **삭제** (2026-08-26 pm-lead 확정) | 본인 전용 개인 데이터 — 상대가 읽는 값이 아니라 "양자 기록 보존" 원칙과 무관하고, 개인정보 삭제 축에 속한다. 로그인 불가로 아무도 못 읽는 죽은 데이터를 남길 이유가 없다 |

## 수용 기준

- [ ] 프로필 카드: 닉네임·프사(이니셜 placeholder)·총 챌린지·승률·승/패/무 표시 (기존 API 재사용, 신규 0)
- [ ] 보관함: **월별 그룹 카드 목록** — 종료된(COMPLETED·EXPIRED 제외 여부는 협의) 챌린지, 카드 탭 → 기존 상세
- [ ] 보관함으로 **홈 7일 노출이 지난 결과에도 도달**할 수 있다 (백로그 히스토리 항목 해소 조건)
- [ ] 로그아웃: 서버 호출로 `refresh_token_hash`·`fcm_token` 이 무효화되고, **그 기기로 푸시가 더 안 온다**
- [ ] 로그아웃/탈퇴 후 로그인 화면으로 이동, 로컬 캐시(토큰·UserInfo) 삭제
- [ ] 탈퇴: 위 정책표대로 — 탈퇴 후 상대가 지난 챌린지 상세를 열면 **깨지지 않고** "탈퇴한 사용자"로 보인다
- [ ] 탈퇴한 사용자의 인증 사진 요청은 깨지지 않는 실패(404 계열)로 처리되고 화면이 대체 표시를 낸다
- [ ] 탈퇴는 **경고 확인 단계**를 거친다 (되돌릴 수 없음 고지)
- [ ] 테스트 결과 숫자로 (Android+iOS)

## 리스크 / 오픈 이슈

- **진행 중 챌린지가 있는 사용자의 탈퇴** — 권장: 막지 않고 자연 판정(탈퇴자는 인증 불가 → 자정 배치가
  기존 규칙대로 처리). 대안: 탈퇴 시점 즉시 포기 처리(판정 규칙 사본이 생겨 비권장). 계약 협의로 확정
- **탈퇴 직후 상대 화면의 정합** — 상세·보관함·랭킹(친구 삭제로 제외)·홈 카드 각각에서 "탈퇴한 사용자"
  표시가 깨지지 않아야 한다. nickname 을 익명값으로 유지하면 계약 변경 0 으로 갈 수 있는지가 관건
- **카카오 unlink 실패 시** — unlink 와 DB 익명화의 순서·부분 실패 처리 (backend 설계)
- 로그아웃의 인증 플러그인 전역 변경 — 기존 401 자동 갱신 회귀 표면
